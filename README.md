# 三色六角碁 (Three Color Hex Go)

**黒・白・赤の3色で遊ぶ、六角格子の変則囲碁**。得点は陣地ではなく**終局時に盤上に残った自分の石数**だけです。

> v1.4.0 は独自ルールの試作版です。CPUは3手先までの候補を限定探索しますが、プロ棋士レベルの囲碁AIではありません。



## v1.4：オンライン耐障害性・スマホ・CPUの品質向上

- 12秒応答がない待機ユーザーをマッチ候補から外し、ホストが25秒準備できない組は待機列へ戻します。ゲストを残したままホストが消えた場合も待機列を復旧します。
- マッチング中止・モード変更・ブラウザ終了時の待機登録を解放し、保留中の非同期通信がキャンセル済みセッションを復活させないようにしました。
- オンライン対局中の棋譜再生を禁止し、ホストが対局を停止してしまう不整合を防止します。
- ランダムマッチのサーバーURLは通常不要な詳細設定へ移動。棋譜JSONのファイル保存、キーボードの1マスTab移動、ピンチ直後の誤着手防止を追加しました。
- 大盤面CPUは局所候補に加え、呼吸点が少ない危険な集団と捕獲可能な相手集団の周辺を優先候補に残します。棋力はベンチマークと実戦で継続検証が必要です。
- Workerはmainのテスト成功を契機として自動デプロイ。待機列の簡易レート制限を追加しました。厳密な不正対策や実回線3台でのE2E試験は別途必要です。
- 運用確認：`/health` はプロセス稼働の確認であり、WebRTCの接続成功や3人対局の成立を保証しません。

## v1.3：PWA・ランダムマッチ・安定化

### オフライン/PWA
- Android Chromeなどで公開ゲームを開き「ホーム画面に追加／アプリをインストール」を選ぶと、PWAとして起動できます。192px/512pxのPNGアイコン、マニフェスト、Service Workerを同梱しました。
- **初回だけ通信が必要**です。初回ロード後はローカル3人交代とCPU対戦、保存済み棋譜、対局分析をオフラインで利用できます。招待制・ランダムマッチは通信必須です。
- 保存はブラウザのlocalStorage内（最大30件）なので、アプリのデータ削除では消えます。必要なら「棋譜をコピー」でJSONを控えてください。

### オンライン招待制
- **3人が接続するまで着手不可**。途中切断した席は空席に戻り、同じ端末から再参加できます（空席へ別の参加者が入る可能性あり）。
- 1手ごとに前の手数・着手内容だけを送る **差分同期** に変更。不一致が出たときと初参加時だけ棋譜全体を送って再同期します。
- 通信の正本は黒（ホスト）のブラウザです。ホストを閉じると対局は終了します。PeerJS Cloud + WebRTCのため、通信環境によって接続できない場合があります。

### ランダムマッチ（Cloudflareで公開済み）
ランダムマッチ用Cloudflare Worker/Durable Objectを公開し、GitHub Pagesから自動接続するよう設定しました。公開マッチング先: https://three-color-go-matchmaker.nao70161994.workers.dev 。ユーザーはサーバーURLを手入力する必要はありません。デプロイとCIの成功は実機3台によるWebRTC対戦成功を保証しません。

既に公開済みのため、通常プレイヤーによるサーバー設定は不要です。3人が「ランダムマッチ」を押すと先着3人でマッチングし、ホストのWebRTC部屋が準備できた後に接続します。2分30秒でタイムアウトし、キャンセルもできます。運営者が別環境へ移す場合はGitHub Actions Variable `MATCHMAKER_URL` で公開URLを上書きできます。

Workerの構成は `worker/wrangler.toml` と `worker/src/index.js` です。対局処理はWorkerに移しておらず、マッチングだけ担当します。

### 描画・CPU・保存
- 「むずかしい」CPUは対局画面でWeb Workerを使い、端末の画面を塞がず着手を計算します。軽い難易度や単一オフラインHTMLは従来処理も利用できます。
- 盤面SVGはサイズが変わらない限りセルを再利用し、石・直近の着手・ヒントが変わった点だけ更新します。
- ローカル対局とオンラインの自動保存先を分離し、ローカル対局は最大30件を履歴として残します。「保存した対局」「棋譜JSONを読み込む」から復元可能です。
- キーボードの矢印キーで盤上の隣接点に移動できます。大型盤面ではこれまでどおり2回タップで着手を確定します。

### CIと運用
- **mainの全テストに成功したときだけ**GitHub Pagesを自動公開するよう変更しました。
- テストにはPWAの実PNGアイコン、ランダム3人組、マッチングサーバーのホスト準備待機、既存のローカル・CPU自動対局を含めます。
- **未検証**：実機3台を異なる回線で接続した際のWebRTC成功率、巨大盤面の長時間バッテリー使用量。リリース後に実機で検証してください。

## v0.8.2：CPUの眼埋め・自アタリ事故を修正

「自分の眼を埋めた後、相手に大きな石の集団を取られる」という問題の追加修正です。

- 以前のCPUは**1〜2マスの閉じた眼の空間**しか保護しなかったため、3マス以上の眼を不用意に埋める問題が残っていました。**同色の連結石で完全に囲まれた8マス以下の空間**は、CPUが着手しない保護対象にしました。
- 眼そのものが閉じていなくても、打った結果自分の集団の呼吸点が**残り1つ**になり、取った相手の石数より危険にさらす自石数が大きい手は避けるようにしました。
- **やさしい・ふつう・むずかしい・CPU3人観戦**で共通の方針です。打つべき安全な手が残っていなければCPUはパスします。
- これらは**CPUの判断方針**です。人間の合法手を禁止するものではなく、ルール・得点・コウの仕様は変更していません。
- 9マス以上の広い空間の判断、本当の二眼の完全な生死判定、コウを含む長手順の読みは未対応です。実戦で再発したら棋譜と局面を使って検証する必要があります。

再現テストでは、3マスの空間を1つ埋めると、残りを相手2色に取られて大集団が消える局面を用意し、CPUが**パスして眼を守る**ことを確認します。

### CPU3人の対局を観戦

対戦モード「**CPU 3人の対局を観戦**」では、黒・白・赤の3人をAIが自動操作します。観戦者は石を打てませんが、**一時停止・再開・1手進める・速度（ゆっくり／ふつう／速い）**を操作できます。CPUの強さは3人に同じ設定を適用します。途中で棋譜再生するとAIの手番も止まり、再生を閉じれば元の観戦状態へ戻ります。

397・469マスなど半径8以上の盤面には「**拡大表示／全体表示**」切り替えがあります。拡大表示では盤をスクロールしながら操作できます（スマホでもページ全体の横スクロールは避けます）。

\`\`\`js
const go=window.threeColorGo;
go.reset({mode:'bots',radius:11,cpuLevel:'easy'});
go.pauseBots();
go.stepBot();               // AIが1手着手
go.getPresentation();       // spectatorPaused, spectatorSpeed, zoomBoard
go.setSpectatorSpeed(180);  // 速い (ms)
go.setBoardZoom(true);      // 盤面を拡大
go.resumeBots();
\`\`\`

AI・Codexなどの検証エージェントは従来の\`getState()\`、\`legalMoves()\`、\`exportRecord()\`、\`importRecord()\`を引き続き利用できます。巨大盤面で「むずかしい」を使う場合、思考時間を抑えるため候補手を事前選別します（全合法手の完全探索ではありません）。大きな盤面ほど長期戦になります。

## v0.6: CPU対戦の研究とゲームバランスの可視化

**三色六角碁のルールは変更していません。** 同じ石数得点、六角盤、呼吸点の判定です。

- 「むずかしい」CPUに **2人の相手による次手の捕獲リスク**の確認を追加しました（\`balanced\` 戦略）。完全な深読みではなく局所的な危険度推定です。以前の \`guarded\` も検証用に残しています。
- AI同士で手番ごとの勝率を測定。黒の優位性を確かめる際は、同じAI3体を使い、引き分けの勝利点を均等配分します。
- **終盤が単調かどうかの代理指標**：盤上占有率、80%以上の盤面充填率、最終3分の1に捕獲がない着手の割合、首位交代回数、共同捕獲数を集計。
- **新旧AI比較**：\`balanced\` 1体と \`guarded\` 2体で、挑戦者を黒・白・赤に交代させながら対局させ、手番位置と強さの影響を分けて観察します。
- 再現可能な乱数シードと棋譜を保存し、問題が出た対局をブラウザの \`importRecord()\` と \`openReplay()\` で検証できます。
- レポートは **GitHub Actions → tests → balance → Artifacts** にJSONとして保存します。

\`\`\`sh
npm test
# 90局の新CPU同士：位置の偏り、終盤の傾向
npm run balance -- --games 90 --radius 3 --seed 20261031 --out reports/balance.json
# 新CPU vs 旧CPU2体：各色30回ずつ、合計90局
npm run balance:matchup -- --games 30 --radius 3 --seed 20261031 --out reports/matchup.json
\`\`\`

**解釈上の注意**：AIの勝率は人間の勝率ではありません。「80%以上埋まる」ことは単調さの可能性を示す指標ですが、プレイヤーが退屈する証拠ではありません。先手有利があっても、十分な人間の対局データが揃うまではコミや得点ルールを変えません。

## v0.5: 棋譜再生・盤面サイズ・CPU改良

- **棋譜再生**：対局中または終局後に「棋譜を再生」から最初・前へ・次へ・最後・スライダーで局面を確認できます。再生中は着手・パス・Undoを無効にし、対局本体を変更しません。「対局へ戻る」で再開します。CPU対戦中は再生中だけCPUの着手も一時停止します。
- **盤面サイズ**：小19マス（半径2）、中37マス（半径3）、標準61マス（半径4）、大91マス（半径5）から選択できます。対局中のサイズ変更は確認のうえ新規対局になります。
- **CPU（むずかしい）**：従来の一手評価に加え、自分の石が呼吸点1になって次のCPUに取られる可能性を限定的にチェックする「guarded」方式に改善しました。網羅的な探索や勝利を保証するものではありません。
- **互換性**：従来のブラウザ自動保存とJSON棋譜はそのまま読み込めます。前のv0.4 APIは維持し、新たに `openReplay()` / `seekReplay(n)` / `closeReplay()` / `getReplayState()` を追加しました。表示用の盤面と実対局の状態を分離しています。

```js
const go = window.threeColorGo;
go.reset({mode:'local',radius:3});
go.play(0,0);
go.openReplay();
go.seekReplay(0);       // 初期盤面の状態を表示
go.getReplayState();    // 表示中の局面をJSONで取得
go.closeReplay();       // 対局へ戻る（石数・履歴は不変）
```

## v0.4: 遊びやすい盤面表示とCPU難易度

- **直前の着手**：盤上に残る直近の着手位置を金色の輪で表示。石が取られた場合は誤解を避けるため表示しません。
- **合法手ガイド**：切り替え式。合法な空点に小さな点が付きます（初期状態OFF）。
- **危険な石**：呼吸点が1つの同色グループに赤い輪を表示（初期状態ON）。危険表示は「次の手で必ず取られる」意味ではありません。
- **CPUの強さ**：やさしい（合法手から乱択）、ふつう（旧baseline）、むずかしい（1手先の捕獲危険も検討するguarded）。この順序は棋力の保証ではなく簡易的なレベル分けです。
- 難易度やガイド表示は対局中に変更可能で、ブラウザ保存・棋譜に含まれます。旧版の保存データも読み込めます。
- 盤面の表示はルール・得点・合法手に影響しません。

## v0.3: 戦略CPU・定量的な自己対局レポート

- CPUは**取れる石**だけでなく、呼吸点が1つの自石の救出、自石の危険、相手の呼吸点を評価する1手読みの戦略AIに変更しました。強い囲碁AIと同等ではありません。
- v0.2 の旧AIは `baseline` として残し、同じ種（seed）で再現可能な比較に使えます。
- CLIでの対局・ブラウザ操作APIは引き続き動作します。ゲームの得点や捕獲ルールは変更していません。
- 対局の勝敗、引き分け、途中打ち切り、手数、占有率、捕獲石数、複数色による共同捕獲を計測します。
- 勝率は同点時に各勝者へ均等配分します。**途中打ち切り局は勝率に含めません**。全員同じAIでの勝率には先手とAI戦術の偏りが含まれます。

```sh
npm test
# 三人とも新AI、300局。棋譜3局分と集計をJSONとして保存
npm run analyze -- --games 300 --seed 2026 --radius 3 --samples 3 --out reports/tactical-300.json
# 旧AI2体 vs 新AI1体。新AIを黒・白・赤に交代させ、各30周（90局）
npm run analyze:compare -- --games 30 --seed 2026 --radius 3 --out reports/rotated-90.json
```

レポートの `sampleRecords[].actions` は既存の棋譜インポート機能で再現できます。
`--games` は通常の分析では実対局数、`--compare` では**各席の実施回数**（実対局は3倍）です。
これはルールの優劣を証明するものではなく、現在の限定的なAI同士の実験です。

## ルール

| 項目 | 内容 |
| --- | --- |
| 人数 | 3人（黒→白→赤） |
| 盤面 | 正六角形。六角マスの中心に石を置く、**6方向接続**の格子 |
| 盤面サイズ | 通常は半径4／61マス。APIでは半径2〜12 |
| 石の連結 | 同色の石が6方向に隣接すると連結 |
| 捕獲 | 集団の空の隣接マス（呼吸点）がゼロになると取り除く。複数色による共同包囲も可 |
| 自殺手 | 禁止（相手を取り、呼吸点を作れる場合は合法） |
| コウ | **全局同形禁止**。パスは例外 |
| 終局 | 3人が連続でパス |
| 得点 | **盤上に残る石1個＝1点**。陣地・アゲハマ・コミは加点しない |
| 勝敗 | 石数最多の色が勝利。同点なら同点者全員が勝者 |

注意：盤上の「死に石」を終了後に自動判定する機能はありません。取る必要のある石は終局前に捕獲してください。

CPUはゲームを極端に長引かせないため、盤面のマス数の2倍の手数を過ぎるとパスする簡易方針です。**強制終局ではなくCPUの行動方針**です。

## 🤖 ChatGPT / Codex / その他AI向け：対局・動作確認

外部エージェントが状態を読み、合法手を選び、実際に打ち、テストできます。詳細は [AGENTS.md](AGENTS.md)。

### 1. ブラウザの操作API

公開サイトまたはローカルサイトを開き、ブラウザのJavaScript実行環境で：

```js
const go = window.threeColorGo;
go.reset({mode:'local',radius:3});
go.getState();            // JSON形式の盤面・手番・得点
go.legalMoves();          // [{q,r}, ...] 合法手一覧
go.play(0,0);             // 黒が(0,0)へ着手
go.pass();                // 現在の色がパス
go.undo();                // 1手戻す
go.exportRecord();        // 棋譜
go.importRecord(record);  // 棋譜を検証して復元
go.autoPlay(100,42);      // 簡易AIが最大100手進める。乱数シード42
```

盤のマスは `g.cell[data-q="0"][data-r="0"]` のような属性で自動操作できます。`getState()` はJSON化できるオブジェクトを返し、UIから独立して結果を確認できます。

### 2. Node.jsで1手ずつAIが対局（外部依存なし）

```sh
printf '%s\n' \
  '{"action":"new","radius":3}' \
  '{"action":"legal"}' \
  '{"action":"play","q":0,"r":0}' \
  '{"action":"state"}' \
  '{"action":"bot"}' \
  '{"action":"export"}' | node scripts/agent-play.mjs
```

入力は**1行1JSON**、出力も**1行1JSON**。利用できる操作は `new`, `state`, `legal`, `play`, `pass`, `undo`, `bot`, `export`, `import`, `simulate`。AIは合法手一覧を確認して任意の手を選べます。自動対局：

```sh
node scripts/agent-play.mjs --selfplay 20 --seed 42 --radius 3
```

20局の対局統計、終了状態、初回の棋譜がJSONで出力されます。

### 3. 自動テスト・実ブラウザ確認

```sh
npm test
```

追加インストール不要。手番、ルール、捕獲、コウ、終局、AI自動対局、JSONLプロトコルをテスト。
