# 20,000局→60,000局：三色囲碁AI比較学習の延長

## 必須条件

前回実験の成功済みGitHub Actions: https://github.com/nao70161994/three-color-go/actions/runs/41610283160

各モデルについて、前回20,000局＝2,500反復の成果物（model-iter2500.pt）を**Adam optimizer・RNG状態ごと**ダウンロードする。モデルJSONのみの再初期化は行わない。

比較する3種類は gnn16 / gnn64 / attn64（64次元4ヘッドAttention×2層）。10特徴量、進行度なし、同じ石数割合−打ち切りペナルティ0.3。対局のパスは常に合法で戦術的な手作業補正なし。

## 40,000局を追加する

GitHub Actions workflow architecture-comparison-60k.yml を使用。各モデル20,000→60,000局、追加40,000局、合計追加120,000局。

- 各段階2,000局＝250反復×8局。20段階を順番に実行。3モデルは各段階で並列。
- 第一段階（22,000局）は前回のrun 41610283160から2,500反復のcheckpointを復元。
- 次段階以降はこのrun内の直前段階成果物からoptimizer/RNG/モデルを再開。
- 学習のパラメータ（seed 20261103、半径2/3/4、temperature1.5、LR0.001、entropy0.015、batch32、sample-stride4、安全上限100×、ペナルティ0.3）は前回と同一。
- 2,000局ごとの評価は同じ未使用seed、半径3・4各18局、balanced＋tactical CPU。自然終局率・石数割合・終局局のみの勝利配分率・序盤パスを保存。
- 完了時には前回の30個と今回の60個、合計90個のcheckpoint artifactから全学習曲線（180評価件）をCSV/Markdownに再構成。
- 前回20,000局のモデルは上書き・消去しない。新しいモデルは実験用であり自動で公開CPUに導入しない。

## 検証

architecture-60k-resume-smoke.yml では前回20,000局の本物の.ptを取得し、全3モデルで8局継続して20,008局になることと、PyTorch/JSパリティを確認。

新workflow成功まで60,000局達成とは言わない。途中の評価結果は各stageのGitHub Actions job summary/Artifactsで確認できる。実行失敗・中断は結果に明記する。

**収束判定への注意**：20,000局でまだ成績が改善中だったため延長するが、60,000局で必ず収束すると保証はない。各局面のテスト相手とseedが固定であるため、強さを確定するには追加seed、3モデル同士の直接対戦を別に実施する必要がある。
